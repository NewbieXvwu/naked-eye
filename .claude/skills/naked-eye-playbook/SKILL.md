# 眼见为实（Naked Eye）：开局清单 + 打法手册 + 验尸流程

项目：眼见为实（Naked Eye），一个只用肉眼玩的 Minecraft agent 客户端（Fabric mod，MC 26.3），只能感知人类玩家能看到、听到的东西；Claude 是大脑，通过 `tools/hc` 操作。**项目归 Claude 所有，有任何不爽的地方都可以直接改代码。** 用户在睡觉或不在时，就自主玩下去，遇到真正过不去的坎再停。

这份 skill 会不断更新：**每死一次都要留下点东西**（见文末"验尸流程"）。

## 0. 开局清单

1. 找到项目：解压后的 `naked-eye/` 目录（云端旧环境里是 `/home/claude/hc26`）。
2. `./setup.sh`（第一次），然后 `./start.sh`；离开前 `./stop.sh`。在云端沙箱里，一轮回复结束后后台进程会被回收，所以每轮都要检查进程还在不在（`pgrep -af java`）；在自己的电脑上，进程会一直开着。
3. `tools/hc obs`。**如果 agent 是死的（`dead: true`），先 `hc respawn`。** 对着死人跑测试，结果全是假失败。
4. 改了 mod 之后：`cd mod && ./gradlew compileJava`，再 `./run_client.sh`，然后 `python3 tools/verify.py`，要求全过（T1–T16）。
5. 速度和暂停：
   - `hc speed 3`：服务器和客户端一起 3 倍速，2 vCPU 的机器上限就是 3 倍。
   - 空闲暂停默认开着：动作一结束世界就冻结。
   - **永远不要用 `/tick sprint` 去打发需要行动的时间**：它只加速服务器，客户端还是 20 tps，等于给怪物开挂。只有把自己封死在坑里过夜时才能用。
6. 收工前：`tick freeze` + `save-all`，重新打包 zip，并用 `tools/replay_cut.py` 把录像里冻结的时间段剪掉。

## 1. 工作方式（用户的长期要求）

- 只用诚实感知；瞄准看得见的实体可以精确，这不算作弊。所有转动都按鼠标整数格走。
- **先手动玩一遍，再写脚本**。看机制本身，不要只看结果数字。
- 不要过度工程。
- 汇报要小步快跑，用简体中文 `SendUserMessage`，语气活泼，观点要明确；重要的事在聊天里说清楚。
- 提交代码时，commit message 末尾带上署名行。

## 2. 打法手册（从死亡里学到的、写不成代码的东西）

**夜晚和出生点**
- 出生点附近树冠很密，白天树荫下也会刷怪；动物少，河边有骷髅骑兵。尽早搬到开阔地带。
- 天黑前要么已经有床，要么挖 3 格下去、把头顶封上（`hole.sh` 的做法：先挖，走进去，再封顶）。夜里空手重生被围死过 4 次。
- **雷暴天气会劈出骷髅骑兵**：它们戴着头盔，白天不会烧死，刷出来就不走了。一打雷就钻到地下。

**食物**
- 难度是 easy，饿肚子只会把血扣到 10 HP，不会饿死；但血少就容易被别的东西打死。
- 饱食度低于 16 时不要疾跑，Baritone 已经强制执行这一条。
- 听声钓鱼很稳：14 竿全中。缺吃的时候是靠得住的兜底。

**背包**
- **圆石永远至少留一组**。背包满了，先扔泥土、沙砾、种子，扔之前先看清楚扔的是什么：一次乱扔把圆石扔光，结果被困死在坑里。
- 水桶永远放在快捷栏里（不要放 0、1 号位，verify 会借用这两格），岩浆反射要靠它。
- 东西掉进岩浆或火里会烧掉；僵尸会捡走掉在地上的装备。
- **两次都是材料凑齐后死在最后一步，东西全丢了**。下次凑齐黑曜石、打火石之后，先把多余的贵重物品存进箱子并做好标记，再去做最后那段有风险的操作。

**怪**
- 苦力怕：能看到它在膨胀，见状就后撤；冷却好了再贴近出刀，充能期间保持 4 m 以上。听到 "Creeper hisses" 就跑，不要停下来想（反射会处理）。
- 残血时举盾后退，不要站桩。
- 追猪、追怪之前先看前方有没有落脚点，被追下悬崖摔死过。

**岩浆、挖矿、传送门**
- 基岩在 y −60..−59，挖钻石的隧道放在 y −56。
- 方块后面记得有岩浆时，`dig` 会拒绝挖。不要随手加 `force`。
- 废弃传送门附近有黑曜石，也有火和岩浆，靠近时要慢，先把水桶拿在手上。
- 爬台阶、站在边缘时要潜行；但**不要在水下按住潜行**（会一直往下沉，反射到气只剩 1/4 才会接管）。

## 3. 技术坑（改代码时要记住）

- `pl.tickCount` 在重生后会归零。凡是计时器一律用 `HonestClient.ticks`（这个 bug 让嘶嘶声反射一直触发，打断了所有任务）。
- 冻结期间客户端照常每秒 20 tick：按住的键会白白倒计时，镜头也能继续转。凡是"按游戏时间算"的逻辑都要用 tick，不要用墙钟。
- 攻击键按住（"正在破坏方块"）时，游戏会忽略右键：放东西之前先松开左键并 `stopDestroyBlock`。
- 26.x 里，客户端往熔炉里快速移动物品会失败（没有配方同步）。
- 用 `/summon` 召唤的骷髅手里没有弓（跳过了自然生成时的初始化），测试时要手动给它配弓。
- verify 里的 `arena()` 会把 agent 从 y225 带着缓降放下去：要先落地，再清掉药水效果。
- ServerReplay 的玩家录制器只有 Flashback 格式支持暂停；ReplayMod 格式要用 `replay_cut.py` 按状态包（协议 777 里的 0x82）剪辑。

## 4. 验尸流程（每次死亡后都要做）

1. **按机制归因**，不要只写"被僵尸打死"。看暂停信息、事件日志和受伤原因（字幕、`hurtDir`、身上的箭），回答：我当时看到了什么？为什么没有反应，或者反应错了？
2. **能写成代码的就写成代码**：做成反射（不暂停、立即执行）或改任务逻辑，再往 `tools/verify.py` 加一条能复现这种死法的测试，跑到全过为止。
3. **写不成代码的，就记进本 skill 的第 2 节**，一条一句，写清楚"什么情况下做什么"。
4. 在 README 当局的复盘里记一行：死因（按机制分类）→ 修复。
5. 每局结束时，用 `propose_skills`（kind 设为 improvement，用 edits 只提增量）把新教训提给用户保存。

## 5. 战绩

- 第二局：挖到钻石（第 3 条命）。
- 第四局：死到第 21 次，两次凑齐下界材料都没能进去。
- 第五局起，开启空闲暂停和 3 倍速。
